## Why this matters

Dégommix ships with a raster-only identity: `assets/branding/logo.png` (2 MB),
`icon.png` and `icon-emblem.png` are AI-generated PNGs with no vector source, and
the whole PWA icon set was cut from them once (`f7853c4 chore(web): pwa icon set
generated from brand emblem`) with no reproducible script. The current icon also
**draws its own rounded frame**, so iOS and Android apply their mask on top of it
and the user sees a frame inside a frame with a shrunken emblem. The owner
validated a replacement direction — **Planche II « Le pion couronné »**: a single
ink game pawn wearing the gold laurel crown on parchment, three shapes, plus a
quadrichrome four-camp variant for festive contexts.

When this lands: the identity has a **committed vector source** (four cuts of one
drawing), the PNG set is regenerated by a **versioned script** so it can never
drift again, the icon is full-bleed and masks correctly on both platforms, and
the README shows the new emblem. The wordmark stays styled text everywhere — it
is never becoming an image.

### Two hard lessons this plan must honor (inlined — you have not seen their sources)

**1. The double-frame lesson.** From the owner-validated logo proposal's
integration notes: *« L'icône actuelle dessine son propre cadre arrondi ; iOS et
Android appliquent ensuite leur masque par-dessus, d'où un cadre dans le cadre et
un emblème rétréci. Règle : l'emblème est plein cadre (le fond va jusqu'aux bords
du SVG), aucun contour de cadre dessiné, et le motif tient dans la zone sûre
maskable (cercle de 80 % centré). »*

Concretely, for the 120×120 viewBox used here: the background rect covers
`0 0 120 120` with **no** rounded corners and **no** stroked outline, and every
drawn point of the motif stays inside the circle of **radius 48 centered on
(60,60)**. The raw pawn drawing does not satisfy this on its own — its base
rectangle corner sits at (29,106), i.e. `sqrt(31² + 46²) = 55.5` from centre — so
the SVG sources below wrap the motif in `scale(0.86)` about (60,60), which brings
that corner to r = 47.7. That transform is load-bearing; do not remove it.

**2. The Turbopack ICO lesson (PR #11, commit `0bf40f2`).** Commit message,
verbatim:

> The ICO embedded a 32x32 PNG encoded as color type 2 (truecolor RGB, no alpha
> channel). Turbopack's ICO decoder only accepts RGBA PNGs, so every page render
> failed during metadata processing with "Format error decoding Ico: The PNG is
> not in RGBA format!", returning 500 in dev. Production `next build` was
> unaffected.

So: `apps/web/src/app/favicon.ico` must be a **real ICO container whose embedded
PNGs are 8-bit RGBA** (not palette, not truecolor-without-alpha). `next build`
will NOT catch a regression here — only `next dev --turbopack` will. The
generation script therefore forces `.flatten()` then `.ensureAlpha()` before
encoding, and step 4 verifies with `file`.

### Tooling actually available (verified during recon — do not re-litigate)

- **`sharp@0.34.5` is already in `pnpm-lock.yaml`** as a dependency of
  `next@15.5.21` (lockfile line 6099). Declaring it explicitly resolves to the
  same version — no new resolution, no new download.
- **`pnpm-workspace.yaml` already allow-lists sharp's install scripts**:
  ```yaml
  allowBuilds:
    esbuild: true
    sharp: true
    unrs-resolver: true
  ```
  So `pnpm install` will not prompt or block on it.
- sharp rasterizes SVG natively (bundled libvips/librsvg). No `resvg`,
  `rsvg-convert`, `inkscape`, or ImageMagick is installed on this machine —
  `which rsvg-convert inkscape magick convert` returns nothing. Only `/usr/bin/sips`
  exists, and sips cannot rasterize SVG or write multi-image RGBA ICOs.
- **Decision (do not substitute another tool)**: add `sharp` as a **devDependency
  of `apps/web`** and drive it from a small committed Node script. It is the only
  option that is already lockfile-resident, already build-approved, cross-platform
  (CI/Railway included), and capable of both SVG→PNG and forcing an RGBA PNG.
  The ICO container is written **by hand in the script** (~25 lines of Buffer
  work) rather than adding a second dependency such as `png-to-ico` — an ICO
  holding PNG payloads is a 6-byte header plus one 16-byte directory entry per
  image, and hand-rolling it is what lets us guarantee the RGBA payload above.

Create `apps/web/scripts/generate-icons.mjs`:

```js
/**
 * Regenerates the shipped PWA icon set from the committed SVG sources.
 *
 * Run with: pnpm --filter @degommix/web icons
 *
 * Two invariants this script exists to guarantee:
 *
 * 1. Every PNG it writes is 8-bit RGBA with an opaque alpha channel. Turbopack's
 *    ICO decoder rejects anything else ("The PNG is not in RGBA format!"), which
 *    makes `next dev` return 500 on every page while `next build` stays green
 *    (see commit 0bf40f2). `flatten()` then `ensureAlpha()` is what enforces it.
 * 2. The SVGs are rasterised at a high density and downsampled, so the 16 px
 *    favicon cut is antialiased rather than nearest-neighboured.
 *
 * The ICO container is written by hand: an ICO holding PNG payloads is a 6-byte
 * header plus one 16-byte directory entry per image, which is cheaper than
 * taking on another dependency just to concatenate buffers.
 */
import { mkdir, readFile, writeFile } from 'node:fs/promises'
import { dirname, resolve } from 'node:path'
import { fileURLToPath } from 'node:url'
import sharp from 'sharp'

const HERE = dirname(fileURLToPath(import.meta.url))
const REPO = resolve(HERE, '../../..')
const BRANDING = resolve(REPO, 'assets/branding')
const PWA_DIR = resolve(REPO, 'apps/web/public/icons-pwa')
const APP_DIR = resolve(REPO, 'apps/web/src/app')

/** App parchment — the manifest background_color and theme_color. */
const PARCHMENT = '#ece0c4'
/** Rasterisation density; 120 px viewBox at 72 dpi baseline, ~5x headroom. */
const DENSITY = 1200

/** Renders an SVG to an opaque 8-bit RGBA PNG buffer of the given square size. */
async function renderPng(svgPath, size) {
  const svg = await readFile(svgPath)
  return sharp(svg, { density: DENSITY })
    .resize(size, size, { fit: 'contain', background: PARCHMENT })
    .flatten({ background: PARCHMENT })
    .ensureAlpha(1)
    .png({ palette: false, compressionLevel: 9 })
    .toBuffer()
}

/** Packs PNG buffers into an ICO container (ICONDIR + ICONDIRENTRY[] + payloads). */
function buildIco(entries) {
  const header = Buffer.alloc(6)
  header.writeUInt16LE(0, 0) // reserved
  header.writeUInt16LE(1, 2) // type: icon
  header.writeUInt16LE(entries.length, 4)

  let offset = 6 + entries.length * 16
  const directory = entries.map(({ size, data }) => {
    const entry = Buffer.alloc(16)
    entry.writeUInt8(size >= 256 ? 0 : size, 0) // width
    entry.writeUInt8(size >= 256 ? 0 : size, 1) // height
    entry.writeUInt8(0, 2) // palette size: 0 = not paletted
    entry.writeUInt8(0, 3) // reserved
    entry.writeUInt16LE(1, 4) // colour planes
    entry.writeUInt16LE(32, 6) // bits per pixel
    entry.writeUInt32LE(data.length, 8)
    entry.writeUInt32LE(offset, 12)
    offset += data.length
    return entry
  })

  return Buffer.concat([header, ...directory, ...entries.map((e) => e.data)])
}

async function main() {
  await mkdir(PWA_DIR, { recursive: true })

  const master = resolve(BRANDING, 'pion-couronne.svg')
  const simple = resolve(BRANDING, 'pion-couronne-simple.svg')

  /*
   * icon-512-maskable is rendered from the same master as icon-512: the artwork
   * is already full bleed with the motif inside the 80 % safe zone, so one cut
   * serves both purposes. The file stays separate because the manifest still
   * declares it, and dropping a declared icon would 404 for installed clients.
   */
  const targets = [
    { out: resolve(PWA_DIR, 'icon-192.png'), src: master, size: 192 },
    { out: resolve(PWA_DIR, 'icon-512.png'), src: master, size: 512 },
    { out: resolve(PWA_DIR, 'icon-512-maskable.png'), src: master, size: 512 },
    { out: resolve(PWA_DIR, 'apple-touch-icon.png'), src: master, size: 180 },
  ]

  for (const { out, src, size } of targets) {
    await writeFile(out, await renderPng(src, size))
    console.log(`wrote ${out} (${size}x${size})`)
  }

  const icoSizes = [16, 32, 48]
  const icoEntries = []
  for (const size of icoSizes) {
    icoEntries.push({ size, data: await renderPng(simple, size) })
  }
  const icoPath = resolve(APP_DIR, 'favicon.ico')
  await writeFile(icoPath, buildIco(icoEntries))
  console.log(`wrote ${icoPath} (${icoSizes.join('/')})`)
}

await main()
```
